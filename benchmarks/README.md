# Benchmarks — 性能・補正品質の基準データと回帰検証

既存パイプライン(テンプレートマッチング → RANSACアフィン推定 → warp)を
固定条件で実行し、**時間・資源・精度**を時系列比較できる形で記録します。
結果はすべてタイムスタンプ付きの新しいディレクトリに書き込まれ、既存の
動画・生成物を上書きすることはありません(誤って上書きが発生した場合は異常終了します)。

```
uv run python benchmarks/run_benchmark.py --mode synth      # 合成動画(正解既知)
uv run python benchmarks/run_benchmark.py --mode video --bg-eval   # 既存動画
uv run python benchmarks/run_benchmark.py --mode synth --repeat 3   # 3回繰り返し
```

## モード

### `synth` — 合成動画による正解検証

`benchmarks/synth.py` が、テクスチャ豊富な基準シーンに **並進・回転・倍率**
(合成中心は画像中心)の既知アフィン運動を与えた動画を生成します。
動画・テンプレートCSV・正解データ(ground_truth.json)はすべて実行ディレクトリに保存され、
同じパラメータ(`--seed` など)で再実行すれば同一入力を再現できます。

正解の座標規約:

- 動画フレーム `k`(1始まり、`k=1` が基準)。基準シーンの点 `p` は
  フレーム `k` で `A[k-1]·p` に現れる(`A[0]` は恒等)。
- ステビライザは `M_k ≈ A[k-1]⁻¹`(フレームk座標 → 基準座標)を推定するはず。

報告される精度指標(区別して報告):

| 指標 | 意味 |
|---|---|
| `matched_error_px` | 追跡点のマッチング位置と正解位置 `A[k-1]·(cx,cy)` の差 |
| `background_residual_px_not_tracked` | **追跡に使わない背景点**の`M_k·A[k-1]·p − p`。追跡点の残差では見えない破綻を暴露する |
| `affine_matrix_error_frobenius` | 推定行列と正解逆行列のFrobenius差 |
| `tracking_failures` | 誤差>2px(閾値)の追跡の割合 |

### `video` — 既存動画の固定条件比較

`--video` / `--csv` で入力とテンプレート定義を指定し、RNGを固定(`cv2.setRNGSeed`)
してから実行します。報告される精度指標:

| 指標 | 意味 |
|---|---|
| `tracked_point_residual_px` | 追跡点の RANSAC フィット残差 `|M_k·(mx,my) − (x,y)|` |
| `ransac_inlier_rate` / `outlier_point_rate` | フレームごとのRANSAC内点割合・外れ点率(追跡失敗率の代理) |
| `background_residual_px_not_tracked`(`--bg-eval`時) | テンプレートROI外のShi-Tomasi特徴点をLK+FBチェックで追跡し、`|M_k·q_k − q_1|` を評価。追跡点とは独立な残留ずれ |

## 記録内容(`report.json` / `summary.md`)

- **工程別時間**: `match`(マッチング)/ `estimate_matrices`(RANSAC行列推定)/ `warp_and_write_streamed`(読み込み→warp→書き出しの逐次処理)を別々に、`pipeline_total`(合計)も記録
- **全体スループット**: frames_per_second、入出力フレーム数
- **資源**: 最大メモリ(RSS。macOSはバイト、LinuxはKiBで取得したものをバイトに換算)、一時ファイル量(逐次処理のため通常0)、出力サイズ
- **品質**: 推定成功(est_fail)と品質合格(quality_fail)を別枠で集計し、閾値を併記した `## Quality` 節。
  診断CSV(`Matched_diagnostics.csv` / `Affined_diagnostics.csv`)をランディレクトリに保存
- **環境**: プラットフォーム、Python、numpy/OpenCV/pandas/Pillow/tqdm のバージョン、Gitコミット、全CLIパラメータ、シード

> メモ: `--repeat > 1` で同一プロセス内で複数回実行した場合、最大メモリは
> プロセス生涯のピーク値となるため各実行の上限目安です。厳密な1実行ごとの
> 値が必要なら`--repeat`を分けて実行してください。

## 既存パイプラインへの最小限の変更

補正工程は PNG 中間ファイルを介さない**逐次処理**になりました
(`VideoCapture → 行列推定 → warp → VideoWriter`)。

- `AffineCorrector.correct()`: 1フレームずつ動画から読み込み、推定したアフィン行列で
  warp して VideoWriter に書き出す。中間PNG(`temp/images`, `temp/converted`)は
  通常時まったく生成しない。メモリはフレーム数に比例して増えない
- `AffineCorrector.precompute()` / `_M()`(キャッシュ付き): 全フレームの行列推定を
  事前に行える。ベンチマークが「推定」と「warp」の時間を分けて計測するために使用
- `AffineCorrector._M()`: 推定統計(フレーム番号・点数・内点数・成否・推定行列)+品質診断
  (採用率・採用点残差・採用点配置の広がり・前フレームからの行列変化量・品質判定)を
  `estimate_stats` に記録し、出力動画の隣に `<出力名>_diagnostics.csv` として書き出す
- `TemplateMatcher.run()`: 読み込んだフレーム総数を `frame_count` に記録。
  マッチングの信頼度診断(スコア/明瞭さ/CCOEFFピーク/ROI端到達/前フレーム位置差/低信頼フラグ)
  を `Matched_diagnostics.csv` としてCSVの隣に書き出す(`Matched.csv` 本体の形式は不変)
- GUI/CLI とも同じ逐次パスを使い、一時ディレクトリの後片付け(`cleanup()` と
  `split()`、PNG中間出力)は廃止
- CLI バッチモード(`--nogui`)は終了時に推定成功/品質合格と低信頼マッチ数を表示する

出力のフレーム対応: **出力フレーム数は入力と同一**で対応は1:1(v0.5.0以降)。
フレーム1はテンプレート抽出の基準フレームとして、アフィン恒等 + 固定透視変換で
そのまま出力する。フレーム2..K は推定アフィン + 固定透視変換で出力し、
`Matched.csv` の `Frame_No = k` が入力・出力のフレーム番号 k と一致する
(フレーム1はマッチング不要のためCSV行を持たない。既存CSVと互換)。

固定透視変換とアフィン行列は単一ホモグラフィに合成され、各フレームの再サンプリングは
1回(v0.4.0以降)。座標対応(どの入力画素がどの出力位置に来るか)は基準版と同一で、
画素値のみ補間回数の差により僅かに異なる(実測: 306フレーム実動画、フレーム平均差
≤ 3.4/255、max差はエッジ部のみ。位相相関で全体シフトなしを確認。詳細はPR #23)。

ベンチの出力フレーム数は実際に動画をデコードして計上し、`frame_count_match` が
入力数との一致を判定する。FPSと再生時間も入出力で記録(可変FPSの入力は平均FPSの
固定フレームレートで書き出される。音声は出力に含まれない)。

## 信頼度評価 (v0.6.0以降)

マッチングと行列推定に**推定成功**と**品質合格**を区別して報告する
(summary.md の `## Quality`)。処理は低信頼でも停止・補間せず、フラグを診断CSVに
記録して出力を続ける。前回行列の無条件流用はしない。

### 記録する指標と閾値(実測データに基づく)

| 指標 | 閾値 | 根拠(実測分布) |
|---|---|---|
| CCORRピークスコア | > 0.95 | 実動画305×5行: min 0.9732 / 合成正常: min 0.9902。遮蔽で0.91まで低下 |
| ピーク明瞭さ(2位との差) | > 0.0002 | 実動画: min 0.0062。繰返し模様: ≈0.0001 |
| CCOEFFピーク(アラーム専用) | > 0.78 | 実動画: min 0.8189 / 合成正常: min 0.854。完全遮蔽で0.48まで低下 |
| ROI端到達 | 端なら低信頼 | 実動画: 0/1525件 |
| 同テンプレート前フレーム位置差 | ≤ 8 px/フレーム | 実動画: max 4.67。動く対象横断: 最大32px |
| RANSAC採用点数/採用率 | ≥ 3 点・≥ 0.6 | 実動画: 採用点{3:7, 4:273, 5:25}、採用率 min 0.600 |
| 採用点の最大残差 | ≤ 2.0 px | 実動画: max 1.26(RANSAC閾値2pxが上限) |
| 採用点配置の広がり | 各軸 std ≥ 10 px | 実動画: x min 231.5 / y min 14.6(退化配置検出) |
| 行列変化量 Δ移動/Δスケール/Δ回転 | ≤ 12 px / 0.02 / 1.0° | 実動画: max 4.65px / 0.006 / 0.243°(約2倍の余裕) |

低信頼時の**拡大ROI再探索**(倍率2倍、画像境界で制限)を実施し、
元のピークよりスコアが **0.005以上** 高い場合のみ採用を入れ替える。
1e-4級のスコア差で入れ替えると合成ベンチの精度が有意に劣化するため
(実測: matched誤差 mean 12.2px / 背景残差 25.5px → マージン導入で正常、
ベースライン mean 8.04px と同等)。

### TM方式比較(TM_CCORR_NORMED vs TM_CCOEFF_NORMED)

正解既知の合成シナリオで両方式を比較 → **採用方式はTM_CCORR_NORMEDを維持**:

| シナリオ | CCORR 誤差 mean/max(px) | CCOEFF 誤差 mean/max(px) |
|---|---|---|
| 正常 | 2.36 / 7.16 | 2.39 / 7.16 |
| 照明変化(乗算+加算ドリフト) | 2.34 / 8.90 | 3.22 / **66.22** |
| 遮蔽 | 5.30 / 50.82 | 5.02 / 52.14 |
| 繰返し模様 | 3.71 / 83.46 | 3.71 / 83.44 |
| 動く対象 | 3.71 / 32.62 | 2.74 / 14.59 |

照明変化ではCCOEFFが最大66pxの誤対応を起こすため方式を変更しない。
一方、**完全遮蔽ではCCORRの正規化スコアが0.98と正常に見えるがCCOEFFは0.5まで
低下する**ため、CCOEFFは第2スコア(アラーム)として採用位置の決定に使わず
検出専用に併用する。コスト: マッチング工程の`matchTemplate`呼び出しが2倍になり
実動画306フレームで match工程 約1.2s(+0.6s)。

### シナリオ評価(粗大誤差>8pxの検出網羅率)

| シナリオ | 粗大誤差行 | 検出率 |
|---|---|---|
| 照明変化 | 35 | 100% |
| 繰返し模様 | 222 | 100%(全フレーム低信頼フラグ) |
| 動く対象 | 14 | 100% |
| 遮蔽 | 30 | 90% |
| 正常 | 0 | FP: 実動画0件 / 合成正常シーン28/300行(明瞭さ閾値に対する合成画像の構造的余裕のなさ) |

遮蔽の残り10%(3行)は遮蔽が解除されつつある遷移帯(CCOEFFピーク0.81〜0.87)で、
どの単一指標でも正常な遮蔽後の追跡と区別できない限界。マッチングレベルで
検出されなかった場合も、行列推定側の採用点フィルタ(RANSAC外れ値除去)が
複数テンプレートが正常なら誤点を拾わない構造になっている。

### 推定成功と品質合格の分離

| 判定 | 意味 | 実測(実動画305フレーム) |
|---|---|---|
| `est_ok` | RANSACで行列が推定できた | 305/305 成功 |
| `quality_ok` | 上記閾値を満たす品質 | 305/305 合格 |

推定に失敗した場合は例外で停止する(品質不良では停止しない)。合成動画では
一部フレームで採用点2点(品質不合格)を検出できており、正常動画では
両判定とも満点であることを基準データとして記録する。

## 制限(スコープ外とするもの)

- 大規模な評価基盤(複数動画の自動SWEEP、DB保存、CI回帰ゲート等)は対象外。
- 合成動画の映像圧縮劣化は mp4v 固定。実行間の厳密なビット一致は保証しない。
- 真の変位>探索範囲のケース(パラメータ側の明示的エラーで停止)。

## 長時間入力のメモリ・検索負荷（v0.10.0）

追跡結果と診断はUTF-8 CSVへ1行ずつ保存し、全追跡行のPythonリストを持ちません。
補正は既存CSVを読み、フレーム番号の索引を1回作成します。各フレームで全行を検索しません。
補正時のCSV本体・索引・行列・推定診断は依然としてフレーム数に比例します。
動画全体のメモリが定数になるという意味ではありません。

`results/issue12-scaling.json` は、固定乱数seed=42の96×128画像をmp4v/30fpsで
301/3001フレーム反復し、3点（24,24 / 100,24 / 24,70）、テンプレート8px・
全探索マージン12pxで比較した結果です。baseline ba92055と変更後を別Pythonプロセスで実行し、
tracemallocで追跡工程・CSV読込＋行列推定のピークを個別に測定しました。
CSV3種の列・行順・数値はpandasで照合し一致しました。
単一実行の時間は参考値で、汎用的な高速化率の保証には使いません。
