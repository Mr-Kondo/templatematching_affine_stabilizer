# 補正処理と限界

[READMEへ戻る](../README.md)

### 1. テンプレート抽出
1フレーム目から、指定された座標を中心に正方形のテンプレート画像を切り出し。

### 2. テンプレートマッチング
各フレームで `cv2.matchTemplate(TM_CCORR_NORMED)` を実行:
- 指定された探索範囲（ROI）内でマッチング
- ピークの左右3点・上下3点を使い、軸ごとに二次補間してサブピクセル単位の位置を求める（交差項を含む2次元二次曲面近似ではない）
- 結果を `Matched.csv` に保存

信頼度評価(v0.6.0以降、詳細は [ベンチマーク文書](../benchmarks/README.md)の「信頼度評価」):
- ピーク相関スコア、明瞭さ、ROI端到達、前フレームからの位置差を計測します。
- `TM_CCOEFF_NORMED` のピーク値は遮蔽検出の第2スコアです。採用位置の決定には使いません。
- スコア不足・明瞭さ不足・ROI端のピークで拡大ROIを再探索し、**明確に高信頼な候補(スコア改善 > 0.005)のみを採用**する(微小差によるピーク入れ替えは性能劣化の実測があるため禁止)
- 低信頼でも停止・補間はせず、診断CSVにフラグを記録する(出力は継続)。前回行列の無条件流用はしない
- 方式は TM_CCORR_NORMED を維持(照明変化で CCOEFF は最大66pxの誤対応、CCORR は8.9pxの実測)

### 3. アフィン変換推定
フレームごとに `cv2.estimateAffinePartial2D(RANSAC)` で2×3の相似変換行列を推定:
- 移動（translation）、回転（rotation）、スケール（scale）を補正
- RANSAC により外れ値の影響を低減
- 品質診断(v0.6.0以降): 採用点数・採用率・採用点の残差・空間配置の広がり・前フレームからの行列変化量(移動/スケール/回転)を記録。**推定成功(est_ok)と品質合格(quality_ok)は別枠で報告**され、品質不合格でも出力は続行する

### 4. フレーム補正
各フレームを**再サンプリング1回**で変換し、`Affined.mp4` に書き出します。

- 固定の透視変換行列 `P`(四隅を内側へ写す台形補正。仕様として維持)をフレームループ外で1度だけ計算
- 推定した 2×3 アフィン行列を 3×3 に拡張し、`H = P·A` として単一のホモグラフィに合成
- `cv2.warpPerspective(H)` で 1 回だけリサンプリング(合成順序は恒等変換・既知の並進/回転で検証済み)
- **フレーム1は基準フレームとして出力**する(アフィン恒等 + 固定透視変換)。出力フレーム数は入力と同一で1対1対応(v0.5.0以降)
- 画角・座標対応は以前の2段方式と同一。画素値のみ、補間回数の差(2回→1回)によりわずかに変化します(v0.4.0: 実測 306フレームでフレーム平均差 ≤ 3.4/255、全体移動なし・端部の黒帯は補間の丸めで僅かに減少)


## 判断条件と適用の限界

CCOEFFの警告と前フレームからの移動量は、低信頼フラグの条件です。それだけでは再探索しません。
ピークが相関面の端なら二次補間の補正量を0にします。位置を細かい単位で推定する処理であり、真の精度を保証しません。
相関の正規化は、遮蔽・反復模様・照明変化への一般的な頑健性を保証しません。上記の誤差は特定の実験条件での実測です。

推定対象は平行移動・回転・一様スケールの4自由度です。せん断・軸別スケールを含む一般アフィンとは異なります。
異なる2組の対応点が最低限必要です。品質判定では内点3点以上などを別に評価します。
軸別標準偏差は配置を見る補助値で、数学的な退化判定の十分条件ではありません。
行列が得られない場合や、NaN・無限大・非正の行列式を持つ場合は推定失敗として停止します。

固定透視変換Pは、幅w・高さhの画像の四隅を(10,5)、(w−11,10)、(w−6,h−11)、(5,h−6)へ写す既存仕様です。
カメラ校正から得たレンズ補正を意味するものではありません。以前の2段方式との画素差の実測値も、全動画での上限ではありません。

視差、非剛体運動、動く前景、遮蔽、反復模様、探索外移動、黒いパディングの多いROI、低模様領域で誤対応し得ます。
追跡点の当てはめ残差、追跡外の背景点の残留ずれ、正解既知の合成誤差は異なる評価です。
診断の合格は、真の位置精度や全画素の品質の保証ではありません。

予測探索・粗密探索・LK・位相相関・ECCは調査した候補です。本番GUI・CLIの選択機能としては提供していません。
比較結果は [開発と検証](development.md) から参照できます。
