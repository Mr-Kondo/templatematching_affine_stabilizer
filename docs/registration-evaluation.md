# 位相相関・ECCの適用条件（Issue #17）

[READMEへ戻る](../README.md)

現時点では両候補を本番の既定処理に追加しません。位相相関には今回の実動画で速度の利点がありましたが、
静止背景領域の選択を前提とする試作です。ECCは背景の大きい残差を減らす一方、処理時間と変換モデルが変わります。

## 比較した処理

再現: `uv run python benchmarks/registration_candidates.py --output 03_output/registration-new.json`。
seed 42/43/44、640×360、61フレーム・5点を使い、平行移動・回転・倍率・照明・動く前景を比較します。
全測定は [issue17-registration.json](../benchmarks/results/issue17-registration.json) を参照してください。

位相相関は上部の静止背景候補（x=32:608、y=16:96）を1/2へ縮小して平行移動の初期値を求め、
初期テンプレートの局所探索に使います。response<0.2または局所照合の低信頼条件で元の固定ROI方式へ戻します。
回転・倍率は位相相関で直接推定せず、照合点のRANSACで求めます。指定した領域が静止背景である保証は、実動画にはありません。

ECCはRANSAC行列の逆行列（基準→現在）を初期値として、1/2画像・最大30反復・epsilon=1e-5で調整します。
OpenCVのMOTION_AFFINEは6自由度です。本番の4自由度相似変換とはモデルが異なり、そのまま同じ補正とみなせません。
再拡大した行列の逆行列を現在→基準へ使います。未収束・不正行列は成功に数えず、元の推定値を保持します。
共通有効画素のマスクを初期変換から作り、黒い無効境界を除きます。合成の動く前景では既知の矩形も除外します。
この前景マスクは正解から分かる好条件の評価で、実動画の自動マスク生成を実装したものではありません。

既知の4/6px並進で、位相相関の移動方向とECC逆変換、未収束時の保持をテストしました。
境界を除かない試作はこの単純例でも偏りが出たため、比較前に有効領域マスクを追加しています。

## 実動画での全体時間

306フレームの読込・追跡・CSV作成・行列推定・補正・動画書込・再読込検証を共通ハーネスで1回ずつ測定しました。
初期値生成とECC反復も時間に含みます。フレーム事前保持・マッチ診断CSV/GUI通知を省く点は#16と同じ制限があります。
ECCの残留ずれは調整後の6自由度行列、他の方式は4自由度行列で計算しています。

| 方法 | 全体秒 | 背景平均px | 背景中央値px | 背景95パーセンタイルpx |
|---|---:|---:|---:|---:|
| baseline | 2.558 | 3.903 | 1.406 | 18.214 |
| phase | 1.971 | 3.903 | 1.406 | 18.214 |
| ecc | 13.154 | 3.487 | 2.221 | 10.104 |

位相相関は今回約23%短く、背景残差はほぼ同じでした。好結果を小さい効果と扱うことはできません。
ただし選択領域への依存と単一動画・単回測定の制限があり、多動画での確認や背景領域指定の仕様を追加する費用を要します。
今回は既定への追加を見送り、再検討する場合は背景条件と低模様時の復帰を先に確認します。

ECCは約5.1倍の時間で背景平均と95パーセンタイルを改善しましたが、中央値は悪化しました。
真の正解がない実動画であり、別のLK背景点も動く前景や視差の影響を受けます。
追加時間・6自由度への変更・実用的な前景マスクの未実装を踏まえ、現行処理への追加は見送ります。
ECCを高速化策や全画素の精度改善として宣伝しません。
